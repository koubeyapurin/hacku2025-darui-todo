LINEヤフー主催の学生ハッカソン **Open Hack U 2025 TOKYO** で、3人チームで開発した作品です。

## 背景

タスク管理アプリが続かない理由は、大きく3つあると考えました。

1. 入力が面倒
2. 無理な予定を立てて失敗する
3. 完璧じゃないと嫌になる

だらしない人は「**発起**(やる気も作業量も多い)→ **収縮**(やる気はあるが作業量が減る)→ **放棄**(どちらも無くなる)」の流れをたどりがちです。だりぃToDo は、収縮の段階で踏みとどまらせて **放棄させない** ことを目指しました。最初の設定だけは一般的なアプリと同じ手間で、その後は最低限の操作で使えるようにしています。

## できること

1. **初期設定**: 時間割と、曜日ごとに課題に使える時間を登録する
2. **課題の追加**: 科目・課題の種類・やりたくなさ(1〜5)・締切を入れると、所要時間を **機械学習(RandomForest)** で予想する
3. **今日やること**: その日に使える時間の **85%** に収まるよう、締切が近い順に「今日やること」を自動で組む。今日やることは、その日に最初に開いたときに1回組みます(あとから足した課題は翌日以降)
4. **途中でやめてもよい**: 作業を途中でやめたら、進み具合(%)から残り時間を減らして次に回す
5. **学び直し**: 実際にかかった時間を記録し、それを使ってモデルを学習し直せる(`train_model.py`)

## 動かし方

Python 3.13 で動作を確認しています。

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python app.py
```

http://127.0.0.1:5000/ を開きます。`database.db` が無ければ、起動時に表とデモ用の初期データ(一般的な時間割と、自動生成した学習用データ)を作ります。

- macOS で 5000 番が使われている(AirPlay など)ときは `PORT=5050 python app.py` のように番号を変えます
- デバッグモードで動かすときは `FLASK_DEBUG=1 python app.py`
- 学習用データを足してモデルを作り直すときは `python generate_and_train.py`(`model/model.pkl` が置き換わります)

### Render へのデプロイ

`render.yaml` に設定があります(Free の Web Service、起動コマンドは `gunicorn -w 1 app:app`)。Render の Blueprint でこのリポジトリを指定すると作成できます。
